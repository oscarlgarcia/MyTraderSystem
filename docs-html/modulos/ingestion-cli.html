Runtime principal: python -m app

Este es el comando que realmente lanza ingestion dentro del pipeline de la aplicacion. En dry consume fixtures deterministas; en paper y live entra por el runtime operativo mas estricto disponible.

Contrato por scope: paper soporta trade y kline; trade en paper queda respaldado por evidencia de replay y parity. live soporta trade y kline, pero trade exige exact recovery e historical-to-live handoff. book queda bloqueado en ambos scopes operativos.

Importante: en paper y live este comando arranca tambien el pipeline de features, por lo que exige metadata de auditoria/contract validation de features. No es un launcher de ingestion aislado, sino del pipeline completo.

python -m app --env dev --mode dry --max-events 100
python -m app --env dev --mode live --duration 600 --max-events 5000 --production-mode

Runtime auxiliar de ingestion

python -m app.ingestion.backfill

Sirve para recuperar historico soportado de kline y trade. Requiere --symbol, --start y --end. --interval solo aplica a kline. --dry-run descarga sin persistir.

python -m app.ingestion.backfill --env dev --symbol BTCUSDT --feed-type kline --start 2024-01-01T00:00:00+00:00 --end 2024-01-02T00:00:00+00:00 --interval 1m --batch 1000 --dry-run

python -m app.ingestion.runner

Runner puntual de ingestion en vivo o con fixtures. Usa --duration, --flush-size y --dry-run.

python -m app.ingestion.runner --env dev --duration 600
python -m app.ingestion.runner --env dev --duration 30 --dry-run

python -m app.ingestion.inspect

Inspecciona eventos normalizados ya persistidos. Permite filtrar por simbolo, fecha y limite.

python -m app.ingestion.inspect --env dev --symbol BTCUSDT --date 2024-01-01 --limit 20

Control plane y recovery

python -m app.controlplane.api

Levanta la UI HTML del modulo sobre FastAPI/Jinja. Es la puerta de entrada para Overview, Streams, Recovery, Audit y otras vistas.

python -m app.controlplane.worker

Consume la cola SQLite de comandos y ejecuta ack_alert, resync_stream y replay_range.

python -m app.ops.quarantine_cli

Permite listar y reinyectar registros de quarantine. Es la CLI de recovery puntual cuando hay DLQ, schema drift o anomalos de market data.

python -m app.ops.quarantine_cli --base-dir . list --symbol BTCUSDT --stream-type kline
python -m app.ops.quarantine_cli --base-dir . replay --env dev --record-id ingestion-dlq.jsonl:1 --write-normalized --report-path docs/validation/quarantine_replay_report.json

Errores y bloqueos habituales

SituacionComando afectadoInterpretacion
Feed live no soportadopython -m app --mode liveEl parser y la matriz de soporte bloquean feeds fuera de trade y kline; book sigue excluido.
Feed paper no soportadopython -m app --mode paperbook sigue fuera del contrato de paper y el arranque lo rechaza explicitamente.
Operational evidence derivada inlinescripts/ingestion_release_gates.pyLa promotion falla si no se entrega un --operational-evidence-path persistido; el gate ya no acepta evidence calculada en proceso.
Provenance incompletascripts/ingestion_operational_evidence.pySi faltan --provenance-source, --runner-id o --trigger, el artefacto deja de ser valido para promotion real.
Metadata contractual de features ausentepython -m app --mode paper/liveEl ciclo completo falla antes de continuar porque el pipeline ya exige auditoria de features fuera de dry.
Rate limit o 5xx del vendorbackfill, canaries, readinessSe aplican reintentos limitados, pero si se agotan el script falla y deja evidencia negativa.
Diffs en shadowpython -m app con --ingest-shadow-modePuede bloquearse si se anade --ingest-shadow-block-on-diff.
Compactacion fallidascripts/ingestion_compact.pyNo debe asumirse consistencia de lecturas largas hasta revisar artefactos y backlog.
