Bundles, Calculo y Uso por Estrategia

Como se calculan las familias de features, cuando usarlas y a que estrategias aportan valor.

Inicio / Modulos / Modulo Feature Store / Feature Engine / Bundles, Calculo y Uso por Estrategia

Proposito

Traducir el catalogo maestro a decisiones practicas de investigacion y operacion: que bundle elegir, de que fuente sale cada familia, como se calcula de forma aproximada y para que tipo de estrategia tiene sentido.

Bundle runtime actual

El runtime default expone una base ampliada sobre el feature set legacy. Hoy calcula precio, retorno logaritmico y agregadores rolling en ventanas 3, 5, 10, 20, 50 con sma, ema, max y min. Eso convierte el runtime default en un bundle de entrada util para estrategias sencillas y para bootstrap de research.

ComponenteEstado actual
Ventanas por defecto3, 5, 10, 20, 50
Agregadores por defectosma, ema, max, min
Aliases operativos destacadosprice, ret_1, sma_3, sma_5, ema_20, max_50, min_10
Compatibilidad con estrategia basicaLa vista de estrategia resuelve sma_3 y hace fallback a sma_5 si solo existe este ultimo.

Como leer "como se calcula"

Las formulas concretas viven en nodos y planners del engine. Esta pagina no intenta duplicar todo el codigo numerico; documenta el origen y la semantica operativa de cada familia:

  • trade: eventos puntuales y ticks agregados.
  • kline: barras con open, high, low, close, volume.
  • portfolio_state: inventario, cash, exposure y limites.
  • execution_reports: acknowledgements, fills, slippage y proxies de latencia.

Cuando usar cada familia

Research

Usa core_market_bundle, trend_bundle, momentum_bundle, volatility_bundle y activity_bundle para explorar ideas amplias. Aqui importa mas la diversidad de familias que la dureza del contrato live.

Backtesting

Anade quality_bundle y exige available_ts, source_cutoff_ts y lineage consistentes. El objetivo es evitar leakage y reproducir decisiones punto en el tiempo.

Paper

Usa solo bundles explicitamente publicados y servibles. Las familias de calidad y riesgo dejan de ser opcionales.

Live

Restringe el set a features y bundles con estado implemented y contrato defendible. Las familias de phase 2 y phase 3 no deben usarse hasta tener fuentes y observabilidad reales.

Que sigue fuera del alcance inmediato

  • Microestructura real basada en book: bid-ask spread, microprice, depth imbalance, queue pressure.
  • Carry y derivados: funding, open interest, basis, skew.
  • Contexto exogeno: macro calendar, news sentiment.

Esas familias ya estan catalogadas para no perder el mapa completo, pero siguen fuera del scope operativo inmediato mientras la plataforma siga centrada en trade y kline.
