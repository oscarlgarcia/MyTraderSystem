Runtime Interno y Estructuras de Ingestion

Como se encadena el runtime, que clases participan y que datos crea o actualiza.

Inicio / Modulos / Modulo Ingestion / Runtime interno

Proposito

Explicar en profundidad el funcionamiento interno del modulo para mantenimiento, debugging y extension, sin asumir conocimiento previo del codigo.

Recorrido principal del runtime

  1. python -m app delega en app.main.run().
  2. run() parsea argumentos con app.config.parse_args() y carga AppConfig desde load_config().
  3. run_cycle() arranca ingestion como primera fase real del pipeline.
  4. run_ingestion_service() delega en collect_events().
  5. collect_events() prepara source, sinks, dedup, checkpoints, shadow y politicas de error/resilience.
  6. ResilientRunner consume el stream, aplica recovery cuando hace falta y drena buffer hacia el handler.
  7. El handler persiste, actualiza metricas y devuelve una lista de IngestionEvent al resto del sistema.

Estructuras operativas del control plane

El runtime no actualiza directamente la UI. En su lugar emite telemetria JSONL que luego se materializa en un read model.

RecordUsoCiclo de vida
RunRecordSnapshot por ejecucion.Se crea o actualiza cuando llegan ingestion_summary y ingestion_health.
StreamStatusRecordEstado por scope.Se actualiza por stream metrics y por health degradado.
AlertRecordAlertas abiertas o acked.Se inserta a partir de operational_alert.
CheckpointSummaryRecordResumen de cursor/checkpoint.Se actualiza con checkpoint_audit_ref.
CommandRequestRecordCola de comandos UI.Se crea al encolar y cambia de pending a running, succeeded o failed.
CommandAuditRecordTrazabilidad de comandos.Se anade por API y por worker.

AccionArtefactosComentario

Politicas internas importantes

  • Backpressure: pause, drop_oldest, drop_newest o fail.
  • Temporal policy: acepta, descarta o falla ante eventos tardios/fuera de orden.
  • Error policy: fail_fast, allow_fallback o degraded.
  • Shadow mode: permite comparar pipelines old-vs-new antes de promotion.
  • Recovery: usa snapshot y checkpoints para recomponer continuidad sin asumir memoria perfecta.
