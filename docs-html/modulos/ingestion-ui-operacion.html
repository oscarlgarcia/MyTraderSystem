UI y Operacion del Control Plane de Ingestion

Que muestra la web interna, como navegarla y como usar recovery sin tocar el hot path.

Inicio / Modulos / Modulo Ingestion / UI y operacion

Proposito

Explicar la UI real del modulo de ingestion y como gestionarla en operacion diaria, con foco en Overview, Streams, Stream detail y Recovery.

Arquitectura de la UI

La UI se sirve desde app.controlplane.api sobre FastAPI/Jinja. Antes de renderizar cada vista, sincroniza un read model construido desde telemetria JSONL. Esto significa que la web muestra una vista materializada y estable, no objetos vivos del runtime principal.

Como gestionar la UI

  1. Entrar por /ui/overview para ver si hay streams degradados, alertas abiertas o comandos pendientes.
  2. Ir a Streams cuando quieras diagnosticar un scope concreto. Usa filtros por estado, simbolo, stream type o texto libre.
  3. Entrar a Stream detail cuando necesites contexto completo: metricas clave, checkpoint y ultimo run relacionado.
  4. Usar Recovery solo cuando ya se ha identificado el scope y la accion apropiada: resync, replay range o replay de quarantine.
  5. Revisar Audit despues de lanzar recovery para comprobar command_id, resultado y errores.

Interpretacion de la informacion visible

SuperficieQue significaComo actuar
Stream severityDeriva de gaps, duplicates, invalid timestamps, heartbeat missed o buffer dropped.Si un stream aparece degradado, revisar detalle y decidir entre inspeccion, resync o replay.
Freshness / last seenUltima actividad observada para el stream o checkpoint.Sirve para detectar lag o streams estancados.
Open alertsAlertas operativas aun no reconocidas.Se pueden ackear desde UI para dejar trazabilidad de triage.
Pending commandsCola aun no ejecutada por el worker.Si se acumulan, el problema suele estar en el worker o en la DB del control plane.
Recent commandsResumen de comandos ya lanzados.Permiten confirmar si recovery ya se intento y con que resultado.

Recovery: que hace cada accion

AccionQue encolaCuando usarla
Resync streamresync_streamCuando el scope necesita resincronizarse desde un rango temporal o cursor claro.
Replay raw rangereplay_range con rango temporalCuando el raw existe y hace falta reconstruir normalized en una ventana concreta.
Replay quarantinereplay_range o replay por record_id/trace_idCuando el payload quedo aislado en DLQ o quarantine y ya se ha validado su reinyectabilidad.

La UI no ejecuta recovery en el request HTTP. Solo encola la orden y deja que el worker la procese de forma asincrona.

Limites de la UI

  • No es una consola live del hot path.
  • No expone memoria, buffers o sockets del runtime principal.
  • No sustituye dashboards externos ni logs de contenedor.
  • No arranca ni detiene el proceso principal de ingestion.
  • No compensa la ausencia de runbooks: la UI ayuda a operar, pero la promotion sigue dependiendo de evidencia y procedimientos.
