Como interpretar la cobertura

  • Unitarios y contratos: confirman reglas locales y compatibilidad de estructuras.
  • Runtime y recovery: protegen continuidad, checkpoints y error handling.
  • Control plane: validan operacion y recovery web sin tocar el hot path.
  • Slow / readiness: aproximan el comportamiento operativo real y el handoff a downstream.
  • Artifacts en docs/validation: son la evidencia auditable para promotion, no solo logs de consola.

Readiness de repo frente a readiness operacional

Las suites del repo demuestran coherencia tecnica y bloquean regresiones, pero no equivalen por si solas a readiness operacional. La promotion requiere artefactos frescos en docs/validation/ y, para live, evidencia de runtime y drills sobre el scope soportado.

El cierre operativo se consolida en ingestion_operational_evidence*.json: ese report agrega freshness por artifact, origen de la evidence, exclusion formal de book y surfaces externas obligatorias para runtime, alertas, logs y promotion.
