Lectura de dependencias verificada

La vista de dependencias observable en el repo no corresponde a una malla de microservicios independientes. Lo verificado hoy es un conjunto de paquetes Python fuertemente acoplados por el entrypoint app.main, con dependencias externas concretas hacia Binance, filesystem local y librerias de runtime como httpx, websockets y pyarrow.

Inventario de dependencias y criticidad

Dependencia o superficieTipoCriticidadUso verificadoEfecto esperado si falla
app.configInternaAltaCarga configuracion, resuelve entorno y parametros de runtime.El proceso principal no arranca o arranca con configuracion insegura.
app.ingestion + app.marketdataInternaAltaCaptura, valida, normaliza y persiste market data y metadata.Se corta la entrada de datos y el pipeline paper/live queda sin eventos fiables.
app.featuresInternaAltaConstruye FeatureVector y mantiene estado cuantitativo.Strategy y risk no reciben insumos consistentes; el ciclo cuantitativo se interrumpe.
app.strategy + app.riskInternaAltaTransforman features en senales y despues en intenciones filtradas.El sistema puede quedarse sin decisiones o producir intenciones invalidas.
app.execution.paper + app.portfolio.stateInternaMediaMaterializan ejecucion paper y estado de portfolio visible en el repo.El ciclo puede ingerir y calcular, pero no consolidar fills, cash ni posiciones.
app.observability + app.opsInternaMediaLogging, release gates, readiness y evidencias operativas.La plataforma pierde visibilidad y validaciones operativas, pero parte del pipeline puede seguir ejecutando.
Binance REST y WSExternaAltaProveedor verificado para market data live, historico y metadata de instrumentos.Sin proveedor no hay live market data, snapshots de metadata ni backfill desde esa fuente.
Filesystem local + pyarrowMixtaAltaPersistencia Parquet, checkpoints, snapshots y evidencias de validacion.Falla la persistencia, se degrada recovery y pueden perderse checkpoints o artefactos.
httpx y websocketsExterna de runtimeAltaTransporte REST y WS para ingestion y metadata.Se degrada o bloquea el acceso a feeds y endpoints remotos.
pytestExterna de desarrolloBajaValidacion automatizada en entorno de desarrollo y CI.No bloquea runtime, pero reduce capacidad de detectar regresiones antes de desplegar.

Dependencias internas y acoplamientos relevantes

RelacionAcoplamiento verificadoImpacto
app.main -> pipeline cuantitativoEl entrypoint importa y coordina ingestion, features, strategy, risk, execution y portfolio.Concentra el wiring principal; un cambio incompatible puede romper todo el ciclo.
app.ingestion.runner / storage / resiliencedocs/dependencies.md los identifica como acoplamiento fuerte para live y persistencia.Un fallo en storage o resilience degrada captura, deduplicacion o durabilidad.
app.common.dto -> resto de modulosLos DTO se usan como contrato tipado compartido entre modulos.Cambios incompatibles en DTO impactan de forma transversal.
app.config -> CLIs y runtimeLas claves y validaciones compartidas gobiernan modos, rutas y politicas.Errores de config afectan arranque, seguridad operativa y rutas de datos.
app.observability.logger -> runtime y opsLogging y trazabilidad estan conectados a entrypoint, ingestion y tooling.Su fallo no siempre tumba el pipeline, pero reduce seriamente el diagnostico.

Fallos esperables por clase de dependencia

  • Si falla Binance o cambia su API, ingestion pierde continuidad, el backfill puede degradarse y los snapshots de instrumentos quedan bloqueados o desalineados.
  • Si falla pyarrow o la ruta de salida no es escribible, el sistema pierde persistencia Parquet, checkpoints y parte de su capacidad de recovery.
  • Si falla app.features, el pipeline puede seguir recibiendo eventos, pero no generar insumos utilizables para strategy y risk.
  • Si falla app.execution.paper o app.portfolio.state, la ruta visible en el repo deja de cerrar el ciclo de decision con estado consolidado.
  • Si falla observabilidad, el sistema puede seguir corriendo parcialmente, pero empeoran MTTR, trazabilidad y confianza operativa.
