Proposito

Documentar el flujo real del market data desde el source de ingestion hasta los consumidores de query, replay, snapshot, control plane y serving. La pagina refleja el core hoy soportado y distingue explicitamente el path experimental de top-of-book.

Secuencia canonica actual

  1. Source / connector: BinanceSource resuelve symbols y streams desde configuracion y, ahora, desde el subscription config persistido.
  2. Normalizacion: el adaptador Binance traduce payloads a eventos canonicos y estampa connector_version.
  3. Persistencia raw: se conserva JSONL append-only con lineage de origen.
  4. Persistencia normalized: ParquetWriter materializa particiones por env, venue, symbol, date y feed type.
  5. Gobierno del dato: el control plane refresca contratos, quality, catalogo, capabilities, delivery y lifecycle.
  6. Serving consumible: query historica, curated serving store, snapshot service, replay service y publication bus exponen superficies mas estables a los consumidores.
  7. Consumers: research, backtesting, paper/live bootstrap, operator tooling y futuros consumers desacoplados.

Contratos y puntos de control

Control de soporte

La support matrix sigue siendo la autoridad para decir si un feed esta aprobado para paper/live.

Control de contrato

El dataset contract registry valida que la particion normalized cumple con el esquema esperado y conserva lineage.

Control de calidad

El quality registry degrada o falla datasets con duplicados, clocks incompletos o orden roto.

Control de entrega

Los delivery contracts hacen explicita la freshness y el modo de completitud esperado por los consumidores.
